# 剧本结构工具（storyboard）技术方案

> 版本：v1，2026-10-31
> 领域概念（节拍、高光、铺垫、贯穿线、单元等）的来源见 [../docs/精品剧剧本框架.md](../docs/精品剧剧本框架.md)。实现前建议先读一遍第三、五、六章。
> 示例数据：[projects/demo/](projects/demo/)，由编剧讨论方提供。它既是演示内容，也是数据格式的参考样例。

---

## 1. 要解决的问题

我们在为 AI 制作的连续剧（单集时长不限）设计剧本结构。一部剧的信息包括：角色、世界设定、贯穿全剧的线、单元故事，以及每集内部按秒排布的节拍、高光、铺垫、情绪曲线。

现在这些信息写在 Markdown 里，有两个问题：

1. **人看不出结构**：几条线在哪里交叉、高光连着哪个铺垫、哪一段没有新东西，读文字看不出来。
2. **AI 读写成本高**：信息都在大文件里，AI 每次都要全量读取，容易漏掉信息，也容易改坏。

## 2. 设计原则

| 原则 | 含义 |
|---|---|
| **AI 是唯一的编辑者** | 所有修改都由 AI（Claude Code）直接改数据文件完成。网页对剧情数据**只读**，不做任何编辑功能；用户能写的只有评论（5.9），评论里提的改动仍由 AI 在对话中出变更单、经用户同意后写入 |
| **人只负责看** | 网页的目标是一眼看清结构，好看、简洁，不堆功能 |
| **小文件 + ID 引用** | 一个条目一个文件，条目之间只用 ID 引用，不复制内容。AI 只读自己需要的那几个文件 |
| **命令行优先给 AI 用** | AI 通过命令查询，按需取一小块，而不是读全量数据 |
| **零依赖** | 只用 Node.js 内置模块，不装任何 npm 包，不需要构建步骤 |
| **改了就刷新** | 数据文件一变，打开着的网页自动刷新 |

## 3. 运行环境

- Node.js ≥ 20（当前机器是 v26），使用 ES Module（`.mjs` 或 `"type": "module"`）
- 不使用任何第三方包；网页用原生 HTML、CSS、JS 和 SVG，不用框架
- 只在本机运行，服务只监听 `127.0.0.1`

## 4. 目录结构

```
storyboard/
├── 技术方案.md            ← 本文档
├── CLAUDE.md              ← 写给 AI 的使用说明（第 10 节规定内容）
├── package.json           ← 只用于声明 "type": "module" 和 bin，无依赖
├── story.js               ← 唯一入口：CLI 命令 + serve
├── lib/
│   ├── load.js            ← 读取、解析、建立索引
│   ├── time.js            ← "m:ss" 与秒的互转
│   ├── query.js           ← index / show / ep / where / chain
│   ├── check.js           ← 检查规则
│   ├── comments.js        ← 评论的读写（comments.json）
│   ├── scaffold.js        ← new 命令的模板
│   └── server.js          ← HTTP 服务 + 文件监听 + SSE
├── viewer/
│   ├── index.html
│   ├── app.js
│   └── style.css
└── projects/
    └── <项目 slug>/
        ├── project.json
        ├── characters/<id>.json
        ├── world/<id>.json
        ├── threads/<id>.json
        ├── units/<id>.json
        ├── episodes/<id>.json
        └── comments.json      ← 评论（网页写入，见 5.9）
```

- 一个 `projects/` 下可以有多个项目。CLI 和服务都通过 `--project <slug>` 选择项目；只有一个项目时默认用它；有多个且没指定时报错并列出可选项。
- 文件名必须等于条目 ID 去掉类型前缀后的部分，比如 `characters/su-tang.json` 的 ID 是 `char.su-tang`。

## 5. 数据模型

### 5.1 通用约定

- **编码**：UTF-8，JSON，2 空格缩进。字段名用英文，内容用中文。
- **时间**：字符串 `"m:ss"`，比如 `"0:05"`、`"3:50"`。程序内部统一换算成秒。允许 `"mm:ss"`。
- **ID**：`<类型前缀>.<slug>`，slug 只含小写字母、数字和 `-`。全项目唯一。

| 类型 | 前缀 | 例子 | 所在位置 |
|---|---|---|---|
| 角色 | `char.` | `char.su-tang` | `characters/` |
| 世界设定 | `world.` | `world.price-tag` | `world/` |
| 贯穿线 | `thread.` | `thread.night-shift` | `threads/` |
| 单元 | `unit.` | `unit.rain-girl` | `units/` |
| 集 | `ep` + 两位数 | `ep01` | `episodes/` |
| 集内条目 | `<集ID>.<前缀><序号>` | `ep01.hl2`、`ep01.su1` | 集文件内部 |

集内条目的前缀：`hl` 高光，`su` 铺垫，`ev` 事件。

- **所有条目都有** `id`（必填）、`name`（必填，显示用的短名）、`summary`（必填，一句话，`index` 命令输出的就是它）、`notes`（选填，决策记录，见下）。
- **`notes` 决策记录**：顶层条目和集内条目（高光、铺垫、事件）都可以有。它是一个数组，**新记录追加在末尾，旧记录不删不改**，决定变了就追加一条新的，保留历史。每条记录：

  | 字段 | 必填 | 说明 |
  |---|---|---|
  | `date` | 是 | `"YYYY-MM-DD"` |
  | `what` | 是 | 定了什么，一句话 |
  | `why` | 是 | 为什么这么定 |
  | `rejected` | 否 | 考虑过、但被否掉的方案，以及原因 |
  | `risk` | 否 | 讨论中提出、但用户决定接受的风险 |
  | `comment` | 否 | 这个决定来自哪条评论，比如 `"c12"`（见 5.9） |

  为了兼容，`notes` 也可以是一段纯文本，网页按一条没有日期的记录显示。
- 枚举值用中文。程序遇到未知的枚举值时**不报错**，`check` 给出警告。

### 5.2 project.json

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `id` | string | 是 | 项目 slug |
| `name` | string | 是 | 剧名 |
| `summary` | string | 是 | 一句话设想 |
| `skeleton` | string[] | 是 | 骨架公式，每集重复的步骤，按顺序 |
| `gridSeconds` | number | 否 | 检查"新东西"的格子宽度，默认 15 |
| `climaxRange` | [number, number] | 否 | 情绪爆点应在的位置比例，默认 `[0.7, 0.85]` |
| `coreQuestion` | string | 否 | 全剧核心问题，一句话。大主题都是它的切面，大结局要回答它（框架第三章"主题从哪来、怎么收小"） |
| `protagonist` | id | 否 | 主角的角色 ID（框架第五章"主角会变，也可以有一段时间不变"） |
| `ensemble` | string[] | 否 | 团队：第一行写借的团队模型、怎么成组和内部的问题，第二行写关系对子和年长者，之后每人一行：谁、想要什么、什么处境、靠哪种发力（打、变、托） |

### 5.3 角色 `characters/<slug>.json`

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `layer` | `"核心"` \| `"单元"` | 是 | 核心层常驻；单元层跟着一个故事 |
| `visual` | string | 核心必填 | 视觉标签：一眼能认出的样子 |
| `ability` | string | 核心必填 | 能力，一句话 |
| `limit` | string | 核心必填 | 能力**不能**做什么 |
| `abilityReflects` | string | 否 | 能力里写着这个人的什么：性格、心结或身份（框架第五章） |
| `limitChoice` | string | 否 | 限制逼他做什么选择，写成"用了就会……"（框架第五章） |
| `anchors` | string | 否 | 核心角色身边能引出单元的人和处境：家人、旧友、过去的事。单元角色挂在这里（框架第五章"单元角色怎么在一个单元里立住"） |
| `growth` | (`"A"`\|`"B"`\|`"C"`)[] | 核心必填 | 变强方式：A 换形态或装备，B 用法升级，C 情绪爆发 |
| `emotion` | string | 否 | 这个角色带来的情绪或话题 |
| `vo` | string \| null | 否 | VO 的语气；`null` 表示这个角色没有 VO |
| `relations` | {`to`: id, `kind`: string, `desc`: string}[] | 否 | `kind` 枚举：克制、互补、组合、镜像、敌对、旧识。`kind` 为"组合"时，`desc` 写两人一起打时怎么分工 |
| `unit` | id | 单元必填 | 所属单元 |
| `fate` | `"退场"` \| `"返场"` \| `"伏笔"` | 单元必填 | 单元结束后的去向 |
| `want` | string | 否 | 单元角色的一个"想要"，最好是人或地方，不是力量 |
| `exit` | string | 否 | 退场的去处，写成一个画面（比如"化成凤凰，小主人坐在背上"）；"打倒了"不算去处 |
| `secret` | string | 否 | 作者知道、观众暂时不知道的东西 |
| `ritual` | string | 否 | 主角有秘密时填：固定动作，以及它怎么推进秘密 |
| `mirror` | id 或 string | 否 | 主角有秘密时填：镜像持有者。以 `char.` 开头时按角色 ID 检查引用 |
| `circle` | {`who`: id 或 string, `desc`: string}[] | 否 | 主角有秘密时填：知情圈，按知道多少分层；`desc` 写知道多少、什么时候、被谁逼出来 |

### 5.4 世界设定 `world/<slug>.json`

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `kind` | `"规则"` \| `"秘密"` | 是 | 规则类早给、给清楚；秘密类晚给、给一半 |
| `truth` | string | 是 | 完整设定，作者视角 |
| `layers` | {`no`: number, `desc`: string}[] | 秘密类必填 | 揭开的层次，从 1 开始 |

某一层在哪集揭开，不写在这里，由集文件里 `kind: "揭示"` 的事件引用（见 5.7），程序反查。

### 5.5 贯穿线 `threads/<slug>.json`

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `kind` | `"大问号"` \| `"成长"` \| `"威胁"` | 是 | 三种贯穿线 |
| `question` | string | 是 | 这条线让观众惦记的那个问题 |
| `ending` | string | 是 | 结局：作者已经想好的终点 |
| `maxGap` | number | 否 | 最多允许连续几集不推进，默认 3 |

推进记录同样由集文件里的事件引用得到。

### 5.6 单元 `units/<slug>.json`

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `episodes` | id[] | 是 | 包含的集，1 到 3 集，按顺序 |
| `emotion` | string | 是 | 这个故事的核心情绪 |
| `question` | string | 否 | 这个单元的对手提出的主题问题，一句话说得清（框架第三章第 4 节） |
| `anchor` | id | 否 | 这个单元挂在哪个核心角色身上，借他已有的感情（框架第五章） |
| `changes` | id 或 string | 否 | 这个单元谁变了：主角、核心伙伴、单元角色或人群 |
| `reveal` | string | 否 | 这个单元知情圈怎么动：谁知道了、怎么被逼出来；没动就留空 |
| `legacy` | {`kind`, `desc`, `ref`?}[] | 是 | 单元讲完后**留下的东西**。`kind` 枚举：角色得到、世界变化、关系变化、遗留问题；`ref` 可指向相关条目 |

### 5.7 集 `episodes/epNN.json`

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `no` | number | 是 | 集号，用于排序 |
| `duration` | string | 是 | 时长 |
| `unit` | id | 是 | 所属单元 |
| `hook` | string | 是 | 前 5 秒的钩子，一句话 |
| `endHook` | string | 是 | 结尾留下的问号 |
| `beats` | Beat[] | 是 | 节拍，按时间排列，不重叠，覆盖全集 |
| `highlights` | Highlight[] | 是 | 高光，至少 1 个，其中**恰好 1 个** `climax: true` |
| `setups` | Setup[] | 否 | 铺垫 |
| `events` | Event[] | 否 | 角色、贯穿线、世界设定在本集的动作 |
| `emotion` | {`t`, `v`, `label`?}[] | 是 | 情绪曲线的关键点，`v` 为 0 到 10 |
| `grid` | {`t`, `new`}[] | 否 | 手写的"这一格新在哪"，补充自动统计（见 6.2 的 W101） |
| `scenes` | Scene[] | 否 | 场次和分镜：剧情的因果链，以及每一场的镜头和台词（见下）。写了场次的集，W118 到 W123 才生效 |

**Beat**

| 字段 | 类型 | 说明 |
|---|---|---|
| `type` | string | 枚举：钩子、钩子升级、教规则、第一回合、压、爆、余波、连接。10 分钟的集可以出现多个"第一回合"或"压" |
| `from`、`to` | time | 起止时间 |
| `label` | string | 选填，显示用 |

**Highlight**

| 字段 | 类型 | 说明 |
|---|---|---|
| `id` | id | `epNN.hlN` |
| `t` | time | 发生时间 |
| `type` | string | 枚举：打斗、亮相、反转、金句、笑点、情绪 |
| `name`、`summary` | string | 名字和一句话描述 |
| `climax` | boolean | 是否为本集唯一的情绪爆发点 |
| `fightType` | string | 选填，`type` 为"打斗"时填这场仗的任务。枚举：亮相、切磋、教学、压制、规则、团战、死斗（框架第四章第 2 节） |
| `fightEnding` | string | 选填，打斗的结局。枚举：打赢、打输、打平、打出关系、送别 |
| `line` | string | 选填，高潮台词（框架第六章"高潮台词怎么写"）。只显示，不检查 |
| `growth` | `"A"`\|`"B"`\|`"C"` | 选填，如果是爆发，用的哪种变强方式 |
| `clip` | boolean | 能否单独切成 15 到 30 秒的片段传播 |
| `setups` | id[] | 撑起它的铺垫，可以跨集引用 |
| `noSetupReason` | string | 选填。确实不需要铺垫时写明原因，W102 不再报 |
| `refs` | id[] | 选填，涉及的角色、设定 |

**Setup**

| 字段 | 类型 | 说明 |
|---|---|---|
| `id` | id | `epNN.suN` |
| `t` | time | 发生时间 |
| `name`、`summary` | string | |
| `kind` | string | 枚举：规则、压、在乎、伏笔。对应高光倒推的三问：观众要先知道什么、先被压到多低、先在乎什么；伏笔是跨集的 |
| `longTerm` | boolean | 选填。为后面的集埋的长线伏笔，本集不兑现时不报 W103 |

**Event**

| 字段 | 类型 | 说明 |
|---|---|---|
| `id` | id | `epNN.evN` |
| `t` | time | 发生时间 |
| `ref` | id | 指向一个角色、贯穿线或世界设定 |
| `kind` | string | 枚举：露面、展开、出场、支援、退场、返场、推进、揭示 |
| `layer` | number | `kind` 为"揭示"且 `ref` 指向**秘密类**世界设定时必填，对应它的 `layers.no`；规则类设定没有分层，不填 |
| `summary` | string | 一句话 |
| `infoGap` | `"观众<角色"` \| `"观众=角色"` \| `"观众>角色"` | 选填，信息差状态 |
| `channel` | string | 选填，信息的投放方式，枚举：VO定格、对白、路人、物件、打斗 |

**Scene（场次）**

一场是同一个地点、连续时间里的一段戏。场次管剧情的因果：这一场谁想要什么、怎么转、为什么接到下一场（框架第六章"为了高光而高光"的坑）。

| 字段 | 类型 | 说明 |
|---|---|---|
| `id` | id | `epNN.scN` |
| `from`、`to` | time | 起止时间。场次按时间排列，不重叠；写了场次就要覆盖全集 |
| `place` | string | 地点 · 内外 · 时间，比如"最强班教室 · 内 · 午后" |
| `wants` | {`who`: id 或 string, `want`: string}[] | 这一场谁想要什么。核心角色第一次出场的那一场必须写他 |
| `turn` | string | 这一场怎么转：局面在哪一下变了 |
| `next` | string | 接下一场的理由；最后一场不填 |
| `shots` | Shot[] | 这一场的镜头，按时间排列 |
| `notes` | 决策记录 | 同上 |

**Shot（镜头）**

| 字段 | 类型 | 说明 |
|---|---|---|
| `id` | id | `epNN.shN`，一集之内按时间顺序编号；评论靠它落到某个镜头、某一句台词 |
| `t` | time | 开始时间，在所属场次之内 |
| `dur` | number | 秒数，不设上限 |
| `size` | string | 景别，枚举：远景、全景、中景、近景、特写 |
| `move` | string | 选填，运镜，枚举：固定、推、拉、摇、移、跟、升降、手持、主观 |
| `frame` | string | 画面：中文写看得见的东西，一两句，不写生成提示词 |
| `lines` | {`who`: id 或 string, `text`: string, `kind`?: string}[] | 选填，台词。`kind` 枚举：对白（默认）、VO、画外 |
| `sound` | string | 选填，音效或音乐 |
| `realizes` | id[] | 选填，这个镜头落实了本集的哪个高光、铺垫或事件 |

### 5.8 引用关系

```
project
  ├─ characters ──relations──▶ characters
  │      └─ unit ─────────────▶ units
  ├─ units ──episodes─────────▶ episodes
  │      └─ legacy.ref ───────▶ 任意条目
  └─ episodes
         ├─ unit ─────────────▶ units
         ├─ highlights.setups ▶ setups（本集或之前的集）
         ├─ highlights.refs ──▶ characters / world
         ├─ events.ref ───────▶ characters / threads / world
         └─ scenes
                ├─ wants.who、shots.lines.who ▶ characters（以 char. 开头时）
                └─ shots.realizes ──▶ 本集的 highlights / setups / events
```

### 5.9 评论 `comments.json`

用户在网页上留评论，AI 在 CLI 里读、讨论、结案。和剧情数据分开放在项目目录下，两边同时写也不会互相覆盖。只有一个用户，所以说话人只分"用户"和"AI"。

```json
{ "comments": [
  { "id": "c1",
    "target": "ep01.sh9#1",
    "quote": "常九九：就一个人。C 级。",
    "status": "讨论中",
    "createdAt": "2026-11-02 15:30",
    "thread": [
      { "by": "用户", "text": "太直白了", "at": "2026-11-02 15:30" },
      { "by": "AI", "text": "……", "at": "2026-11-02 15:41" } ],
    "resolution": { "status": "已采纳", "note": "改了什么、为什么", "by": "AI", "at": "…" } } ] }
```

| 字段 | 说明 |
|---|---|
| `id` | `c` 加序号，不回收 |
| `target` | 任何条目的 ID；指向某一句台词时写 `镜头ID#第几句`（从 1 开始） |
| `quote` | 评论时的原文：台词、镜头画面，或条目的名字和一句话。之后内容改了，也看得出当时评的是哪句 |
| `status` | 待处理（刚写）→ 讨论中（有人回复）→ 已采纳 / 已拒绝 / 已解决。结了案的被用户再回复，回到讨论中 |
| `thread` | 对话，按时间追加 |
| `resolution` | 结案：结论和改了什么。采纳的改动照常写进对应条目的决策记录，`comment` 字段写这条评论的 ID |

网页只能新建评论、回复、关掉自己的评论（记为已解决）；采纳和拒绝由 AI 在 CLI 里做，改剧情数据仍然要按变更单走，用户在对话里同意以后才写。

## 6. 命令行（给 AI 用）

### 6.1 命令

统一形式：`node story.js <命令> [参数] [--project <slug>] [--json]`

- 默认输出**紧凑文本**：一个条目一行，行首是 ID，方便 AI 接着用 ID 追问。
- `--json` 输出结构化数据。
- 退出码：成功 0；参数错误或找不到条目 2；`check` 发现错误级问题 1。

| 命令 | 作用 |
|---|---|
| `index [--type <类型>]` | 列出所有条目，每行 `ID  名字  一句话`。按类型分组：项目、角色、世界、贯穿线、单元、集。AI 进入项目时先跑它 |
| `show <id> [<id>...]` | 输出一个或多个条目的完整内容。集内条目（如 `ep01.hl2`）也能直接查 |
| `ep <集ID或集号> [--from <t>] [--to <t>] [--only <字段,...>]` | 输出一集，或一集里的一个时间段。`--only` 只要某几类，比如 `--only highlights,setups` |
| `script <集ID或集号> [<场次ID>]` | 按剧本格式输出一集或一场：场次标题、谁想要什么、怎么转，下面逐个镜头写景别、运镜、画面和台词。给 AI 读，也方便复制 |
| `comments [--status 未完成\|<状态>] [--target <条目ID或集ID>]` | 列出评论，每行：ID、状态、目标、原文、第一句和最新一句。`未完成` 是待处理加讨论中 |
| `comment <评论ID>` | 一条评论的目标、原文和整段对话 |
| `comment add <目标ID[#第几句]> <内容>` | 以 AI 的身份发起一条评论（比如自己发现的问题，留给用户看） |
| `comment reply <评论ID> <内容>` | 以 AI 的身份回复 |
| `comment resolve <评论ID> --as 采纳\|拒绝\|解决 [--note <改了什么、为什么>]` | 结案 |
| `where <id>` | 某个角色、贯穿线或设定在哪些集、什么时间出现，按时间排列。包括事件、高光的 `refs`、单元的 `legacy.ref` |
| `chain <高光ID>` | 某个高光的铺垫链：列出它引用的每个铺垫，标注所在集和时间，以及和高光相隔多久 |
| `timeline [<集ID>]` | 不带参数：全季概览，每集一行（时长、单元、爆点时间、高光数、问题数）。带参数：这一集按时间排好的所有条目，一行一个 |
| `check [<集ID或条目ID>] [--level error\|warn\|info]` | 运行检查规则（见 6.2）。不带参数检查整个项目 |
| `new <类型> <slug>` | 按模板创建一个新文件，必填字段留空字符串，方便 AI 填写。类型：character、world、thread、unit、episode |
| `serve [--port 4173] [--host 0.0.0.0]` | 启动网页，所有项目共用一个服务，见第 7 节 |

### 6.2 检查规则

| 编号 | 级别 | 规则 |
|---|---|---|
| E001 | error | 引用了不存在的 ID |
| E002 | error | ID 重复，或文件名与 ID 不一致 |
| E003 | error | 时间格式错误，或超出本集时长 |
| E004 | error | 一集的 `climax: true` 不是恰好 1 个 |
| E005 | error | 节拍重叠，或没有覆盖全集 |
| E006 | error | 必填字段缺失（按第 5 节的表；核心角色的 visual、ability、limit、growth 属于必填；写了场次时镜头的 id 必填） |
| W101 | warn | 空格子：某个 `gridSeconds` 宽的格子里没有任何高光、铺垫、事件、节拍起点或 `grid` 记录，这里可能是流失点 |
| W102 | warn | 高光没有铺垫，也没写 `noSetupReason` |
| W103 | warn | 铺垫没有被任何高光引用，也没标 `longTerm` |
| W104 | warn | 铺垫出现在它所支撑的高光之后 |
| W105 | warn | 情绪爆点不在 `climaxRange` 范围内 |
| W106 | warn | 贯穿线连续超过 `maxGap` 集没有推进 |
| W107 | warn | 单元的 `legacy` 为空 |
| W108 | warn | 单元里某一集没有高光（单元没讲完，单集也要给爽点） |
| W109 | warn | 第一个节拍不是"钩子"，或钩子长于 5 秒 |
| W110 | warn | 相邻两个高光间隔超过 2 分钟 |
| W111 | — | 已删除：单集时长不设上限 |
| W112 | warn | 单元角色没有 `fate` |
| W113 | warn | 枚举值不在列表里 |
| W114 | warn | 标了 `longTerm` 的铺垫，到最后一集都没有被引用 |
| W115 | warn | 决策记录格式不对：不是数组（纯文本除外）、缺少 `date`/`what`/`why`、日期不是 `YYYY-MM-DD`，或日期早于上一条（说明不是追加在末尾） |
| W116 | warn | 一集里有两场或以上 `fightType` 为"死斗"的高光（不要每场都打成死斗） |
| W117 | warn | 第 1 到 3 集里，某一集没有 `type` 为"打斗"或"亮相"的高光（试播集和前几集不要让打斗退后） |
| E007 | error | 场次重叠或超出本集；镜头时间不在所属场次之内，或镜头之间重叠 |
| W118 | warn | 场次没有写 `turn`（没有转折的场就是水） |
| W119 | warn | 场次没有写 `next`（最后一场除外）：前后两场的因果断了 |
| W120 | warn | 核心角色在全剧第一次出场的那一场，`wants` 里没有他（框架：想要在第一次登场就说出口） |
| W121 | warn | 写了场次的集里，某个高光或铺垫没有被任何镜头的 `realizes` 落实 |
| W122 | warn | 台词说不完：一个镜头里台词的字数按每秒 4 个字估算，超过了镜头的 `dur` |
| W123 | warn | 写了场次的集，场次没有覆盖全集 |
| W124 | warn | 没处理完的评论指向的条目或台词已经不在了（被删了，或改了 ID） |
| I213 | info | 有没处理完的评论（待处理或讨论中） |
| I201 | info | 情绪爆点前 15 秒内没有低于爆点 3 分以上的情绪点（爆发前缺少安静） |
| I202 | info | 全集没有 `clip: true` 的高光 |
| I203 | info | 核心角色没有写 `abilityReflects`、`limitChoice` 或 `anchors` |
| I204 | info | `type` 为"打斗"的高光没有填 `fightType` |
| I205 | info | `project.json` 没有写 `coreQuestion` |
| I206 | info | 单元没有写 `question` 或 `anchor` |
| I207 | info | 单元角色没有写 `want` 或 `exit` |
| I208 | info | 写了 `anchor` 的单元数已经不少于核心角色数，仍有核心角色没当过任何单元的 `anchor`（核心角色要轮流当情绪中心） |
| I209 | info | `project.json` 没有写 `protagonist`（主角）或 `ensemble`（团队） |
| I210 | info | 主角写了 `secret`，但没有写 `ritual`、`mirror` 或 `circle` |
| I211 | info | 主角有秘密，按首集排序后连续 3 个以上单元的 `reveal` 为空 |
| I212 | — | 已删除：主角连续几个单元在变不是问题 |

输出格式，每行一条：

```
W101 ep01 1:15–1:30  空格子：这15秒没有新东西
W102 ep02.hl1        高光「影子交出钱包」没有铺垫
```

## 7. 本地服务

`node story.js serve` 启动，默认监听 `0.0.0.0:4173`（`--host 127.0.0.1` 只允许本机；端口被占用时报错退出，不要自动换端口），终端打印访问地址和每个项目的路径。一个服务同时提供所有项目，`serve` 不需要 `--project`。

| 路径 | 返回 |
|---|---|
| `GET /` | 项目列表页（`viewer/index.html`，不带项目） |
| `GET /<slug>` | 该项目的查看器（`viewer/index.html`，注入项目 slug）；项目不存在时返回 404，页面显示项目列表和提示 |
| `GET /viewer/*` | 静态文件 |
| `GET /api/projects` | 项目列表 |
| `GET /api/project?project=<slug>` | 整个项目的数据，已解析，附带反查结果（每个条目被哪些集引用）和 `check` 结果 |
| `POST /api/comments?project=<slug>` | 新建评论，body `{ target, text }`，说话人记为用户 |
| `POST /api/comments/reply?project=<slug>` | 回复，body `{ id, text }` |
| `POST /api/comments/close?project=<slug>` | 用户关掉自己的评论，记为已解决，body `{ id }` |
| `GET /api/stream?project=<slug>` | SSE。项目目录下任何文件变化（防抖 200ms）后推送 `event: change`；文件解析失败时推送 `event: error`，带文件路径和错误信息 |

- 文件监听用 `fs.watch(dir, { recursive: true })`。
- 网页**不需要**分块加载：一个项目的数据量很小，一次拿全量即可。按需读取只针对 AI 的 CLI。
- 某个文件 JSON 格式坏了，服务不能崩溃：其他数据照常返回，坏掉的文件出现在 `check` 结果里，网页顶部显示红色提示条。

## 8. 网页查看器

### 8.1 总体

- 剧情数据只读：没有任何编辑、拖拽、保存功能。唯一能写的是评论（见 5.9 和 8.6）。
- 顶部栏：项目名 · 三个标签页（全季 / 单集 / 资料）· 检查徽标（"2 错误 · 5 警告"，点击展开问题列表）。
- 右侧详情面板：点击任何条目时滑出，显示它的完整字段、**决策记录**（`notes` 全文，最新的在最上面，不截断）和它被引用的地方；点击里面的 ID 可以跳转。按 Esc 关闭。
- 收到 SSE `change` 后重新拉取数据，保持当前的标签页、选中的集和打开的面板。
- 项目在路径里，当前标签页、选中的集记在 URL hash 里（如 `/demo#ep/ep02`），刷新不丢。顶部栏左侧有"storyboard"链接回到项目列表。

### 8.2 单集视图（最重要）

原则：**文字直接写出来，图只用来看形状。** 只放符号、要靠悬停才知道内容的设计不可取。

从上到下：

1. **集选择器**：一排按钮，左边框是所属单元的颜色。
2. **标题区**：集号和集名、一句话；右侧三个信息块：时长、单元、爆点（点爆点即选中它）。
3. **钩子**：前 5 秒钩子和结尾钩子并排两张卡片。
4. **时间线**（SVG，按容器的实际像素宽度绘制，字号固定，不随窗口缩放；窗口变化时重画，最小 960px，更窄时横向滚动）：
   - 时间尺；爆点在时间尺上标"◆ 爆点 m:ss"，并有一条贯穿全图的虚线
   - 情绪曲线：有 `label` 的点直接写出标签
   - 节拍：色块，放得下就写"类型 · 标签"，放不下只写类型
   - 高光：按类型着色的星形（爆点为菱形），**名字直接写在标记下方**；可切片的加 ✂
   - 铺垫：按类型着色的空心圆（长线伏笔为虚线），名字直接写出
   - 标签放不下时自动错开成多行（高光、铺垫最多 3 行），仍放不下才只保留标记
   - 角色、贯穿线、设定：每个一行，行名用它的颜色；事件点旁写事件类型（揭示写"第 N 层"）；参与高光但没有事件的，画小空心点
   - 15 秒格：有内容为浅绿，空格子为红框并写"空"
   - **点击高光即选中**：选中后它和本集铺垫之间画出连线并一直保留，其他标记变淡；时间线上方出现一行提示，列出它的全部铺垫（跨集的标"← epNN"）。再点一次或按 Esc 取消
5. **按时间顺序的清单**：以节拍为分段标题（带节拍颜色），段内按时间列出铺垫、事件、高光、画面记录（`grid`）、空格子。每行：时间 · 彩色标签 · 名字和一句话。高光行列出"← 铺垫"，铺垫行列出"→ 兑现"（跨集查找），都可以点。检查问题直接显示在对应行下面。
6. **分镜**（写了场次的集才有），按场次排列，像翻漫画一样读：
   - **场次卡**：场号、地点；"谁想要什么"每人一行；"转"写出这一场的转折；右下角一个箭头写出"→ 下一场：接下一场的理由"
   - **分镜条**：每个镜头是一格漫画，宽度按 `dur` 缩放（有最小和最大宽度），一行放不下就换行
     - 格子左上角写景别，运镜用一个箭头符号加文字（"→推"）；景别用画框的样式区分，特写边框最粗，远景上下留黑边
     - 画面文字写在格子里
     - 台词是对话气泡：每个角色固定一个颜色，按角色在项目里的顺序从调色板取，不是角色设定；非角色 ID 的说话人用灰色；VO 是格子顶部的方形旁白框；画外是虚线气泡
     - `sound` 写在格子底部，前面加 ♪
     - 落实了高光的格子右上角带星标和高光名，爆点那一格加宽、换强调色边框；落实了铺垫的格子带一个小图钉
     - 格子底部写开始时间和秒数
   - 场次上方有一条和镜头对齐的细情绪曲线
   - 点击格子打开详情面板，显示它落实的高光、铺垫、事件
   - 右上角可以切换成"纯文本"，按剧本格式显示，方便复制
7. **本单元留下的东西**。

清单行和时间线标记互相联动：悬停一边，另一边同时高亮。

### 8.3 全季视图

看板，不是图。每个格子里直接写文字，不需要悬停。

- 横向是集，纵向是行；每一行都是同样列宽的网格，保证对齐；集多时横向滚动。
- 第一行：每集一张卡片：顶边是单元颜色；集号、时长、问题数；集名；爆点（按高光类型着色）；钩子（最多两行）。点击进入单集。
- 情绪行：每集的情绪曲线缩略图，爆点标圆点。
- 单元行：单元横跨它的几集，显示为色带，写出单元名和核心情绪。
- 分组：贯穿线 → 核心角色 → 单元角色 → 世界设定（只列出在事件里出现过的），每组有小标题。
- 格子内容：这一集里涉及它的事件，每条一个彩色左边框的小块，写"事件类型 + 一句话"。角色格另外列出它参与的高光名。
- 贯穿线连续超过 `maxGap` 集没有推进，这几格标红并写"断档"。
- 角色排序：核心在前，同层里被引用越多越靠前。

### 8.4 资料视图

卡片网格，按组排列：核心角色、单元角色、贯穿线、世界（规则类 / 秘密类）、单元。每组标题带颜色圆点和数量。

- 卡片顶边是该条目的颜色。角色卡显示：视觉、能力、限制、变强方式、情绪、VO（核心角色没有 VO 时写"没有 VO"）、关系、秘密。
- 秘密类设定逐层列出，已揭开的标出在哪一集，未揭开的写"未揭开"。
- 有决策记录的卡片显示一个可展开的"决策记录 N 条 · 最新：……"，展开后显示全部记录；展开不会打开详情面板。
- 卡片底部显示"出现在：ep01 ep02"，可以点击。

### 8.5 视觉

- 颜色全部定义成 CSS 变量，浅色和深色各一套，跟随系统（`prefers-color-scheme`）。
- **颜色表达类别**，每类固定：
  - 高光类型：打斗红、亮相紫、反转蓝、金句金、笑点绿、情绪粉
  - 铺垫类型：规则青、压灰、在乎粉、伏笔金
  - 核心角色蓝；单元角色用所属单元的颜色；贯穿线：大问号紫、威胁橙、成长绿；世界设定：规则青、秘密品红
  - 节拍：从冷到热再回落（钩子蓝 → 教规则米 → 第一回合绿 → 压紫 → 爆橙 → 余波灰）
  - 情绪曲线粉；问题：错误红、警告琥珀
- 时间线上方显示颜色图例。
- 字号：正文 15px，最小 12px；标题 19 到 28px。圆角卡片、轻阴影，大量留白。
- 字体：系统字体栈，中文优先 `PingFang SC`、`Microsoft YaHei`。
- 宽度 900px 以下简化布局（隐藏顶栏简介，钩子卡片改为上下排列，清单改为两列）。

### 8.6 评论

- 分镜里的每个镜头、每一句台词、每张场次卡，以及任何条目的详情面板，都有一个 💬 按钮；有没处理完的评论时显示数量并标红。
- 点 💬 打开详情面板，底部是这个地方的评论：每条显示状态、原文和对话（我的在左，AI 的在右），可以回复、关掉。镜头的面板里可以选"整个镜头"或"第几句"再写。
- 顶栏"评论"标签页：列出全部评论，可筛"没处理完"和"全部"；标签上显示没处理完的数量。
- 没提交的草稿在数据刷新时保留；正在写评论时 Esc 不关面板。

## 9. 非功能要求

- 示例项目（3 集、十几个条目）下，任何 CLI 命令应在 200ms 内返回。
- 所有解析错误都要指出**文件路径**和**原因**，不能只抛出堆栈。
- CLI 输出不使用颜色控制字符（AI 读取时是噪音）；`--json` 输出必须是合法 JSON。
- 代码量参考：`lib/` 合计 800 行以内，`viewer/` 合计 1200 行以内。

## 10. CLAUDE.md 的内容要求

实现完成后，在 `storyboard/CLAUDE.md` 写给 AI 的说明，至少包括：

1. 这个工具是干什么的，数据在哪，领域概念去哪看（链接到框架文档）。
2. **工作流程**：先 `index` → 按需 `show`、`ep`、`where` → 直接编辑对应 JSON 文件 → 跑 `check` → 修复错误级问题。
3. **不要**一次读取整个 `projects/` 目录。
4. 新建条目用 `new`，ID 和文件名的规则。
5. 改 ID 时要同时改所有引用它的地方（用 `where` 找）。
6. 各字段的含义，可以直接链接到本文档第 5 节。

## 11. 验收标准

- [ ] 三个视图都能看，浅色和深色都正常

## 12. 暂不做

- 镜头级（分镜）数据，以后可能作为集文件里新的一层加进来
